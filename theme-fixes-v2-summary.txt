1) [ROOT CAUSE] index.css — token `info` & `offline` tidak punya varian tema terang
--------------------------------------------------------------------------------
Lokasi   : frontend/src/index.css
Masalah  : Semua token status lain (accent, success, warning, danger, online,
           los, dyinggasp) sudah punya versi "di-gelapkan" khusus untuk
           html.light supaya tetap kebaca di background terang. Tapi
           --color-info (#38BDF8, biru terang) dan --color-offline (#6B7A99)
           TIDAK pernah di-override — jadi di tema terang, dua warna ini
           tetap pakai versi yang didesain untuk background gelap.
           Dipakai di 36 tempat / 12 file (info) dan 41 tempat / 7 file
           (offline) — panel info SFP/optical, header tooltip, badge
           offline, dll di hampir semua halaman.
Perbaikan: Tambah --lt-info (#0284C7) dan --lt-offline (#64748B), lalu
           override --color-info dan --color-offline di blok html.light
           sama seperti token lainnya.
Dampak   : Ini yang paling mungkin jadi penyebab utama kesan "belum
           konsisten" di banyak halaman sekaligus — karena satu token ini
           dipakai luas, bukan cuma di satu komponen.


2) components/RackDiagram.tsx — rack diagram untuk OLT C320 (model utama)
--------------------------------------------------------------------------------
Lokasi   : frontend/src/components/RackDiagram.tsx
Masalah  : Komponen ini dipakai untuk model C320 (model utama/paling umum
           menurut README) dan HAMPIR SELURUHNYA memakai warna Tailwind
           hardcoded yang didesain untuk tema gelap saja: tombol Enable/
           Disable Port pakai bg-red-950/60, bg-green-950/60, message box
           pakai bg-green-950/40, teks status ONU pakai text-green-400/
           text-red-400, traffic in/out & VLAN chip pakai text-blue-400/
           bg-blue-950. Di tema terang, ini semua akan tampil sebagai
           "pulau gelap" (background 950-scale nyaris hitam) yang sangat
           kontras dan tidak nyambung dengan UI terang di sekitarnya.
Perbaikan: Semua diganti ke token tema (success/danger/info/warning) yang
           sudah otomatis menyesuaikan tema, sama seperti pola yang sudah
           benar di komponen lain (mis. panel Optical Module Info di file
           yang sama, yang memang sudah benar dari awal).
Cara tes : Buka halaman OLT Configuration untuk OLT bermodel C320, klik
           port PON/uplink untuk buka detail modal, toggle tema — pastikan
           tombol Enable/Disable Port dan semua teks status ikut berubah.


3) components/rack/ZteRackDiagram.tsx — sisa titik dari audit round 1
--------------------------------------------------------------------------------
Lokasi   : frontend/src/components/rack/ZteRackDiagram.tsx
Masalah  : Patch round 1 baru menutup 4 titik yang pakai variant `dark:`.
           Ternyata masih ada pola yang SAMA seperti temuan #2 di atas
           (tombol toggle + message box red-950/green-950) yang lolos dari
           audit pertama karena tidak pakai `dark:` sama sekali — cuma
           hardcoded warna gelap secara langsung.
           Ditemukan juga:
           - Tooltip slot (hover kartu OLT) pakai text-teal-400/
             text-green-400/text-red-400/text-amber-400, padahal tooltip
             PORT di file yang sama (beberapa baris di atasnya) sudah benar
             pakai text-accent/text-success/text-danger/text-warning —
             dua tooltip di komponen yang sama pakai "bahasa warna" beda.
           - Header suhu slot: saat suhu masuk zona panas (>=50°C),
             background jadi merah/oranye/amber pekat (fixed, tidak ikut
             tema — ini oke), TAPI teksnya pakai text-tx1 yang di tema
             terang berubah jadi hampir hitam → teks nyaris tidak kebaca
             di atas background merah/oranye tersebut.
           - Badge & legend "Dying Gasp" pakai bg-purple-600 (ungu),
             padahal status yang sama di tooltip PORT sudah dilabeli
             text-warning (amber) — dan token --color-dyinggasp yang
             sudah ada di index.css pun nilainya = warna warning, bukan
             ungu. Jadi ada 2 warna berbeda untuk 1 status yang sama.
           - Grid statistik ONU (Online/Offline/LOS) pakai text-green-400/
             text-red-400, sama seperti temuan di RackDiagram.tsx.
Perbaikan: Semua disamakan ke token tema; khusus header suhu, teks
           dipaksa putih HANYA saat background panas aktif (karena
           background itu sendiri sengaja fixed, jadi teksnya juga perlu
           fixed supaya tetap kontras di kedua tema); Dying Gasp disatukan
           jadi warning di semua tempat (badge, legend, tooltip).


4) AllOnus.tsx & Customization.tsx — preset warna RX Power Range
--------------------------------------------------------------------------------
Lokasi   : frontend/src/pages/AllOnus.tsx, frontend/src/pages/Customization.tsx
Masalah  : Fitur "Configurable RX power color ranges" punya 7 pilihan warna
           (Green/Yellow/Red/Blue/Purple/Orange/Gray). Green/Yellow/Red
           sudah benar pakai token tema, tapi Blue/Purple/Orange/Gray masih
           hardcoded shade -400/-500 yang kontrasnya turun signifikan di
           tema terang (dirancang untuk background gelap).
Perbaikan: Tambah 4 token tema baru di index.css: --color-rx-blue,
           --color-rx-purple, --color-rx-orange, --color-rx-gray — masing-
           masing punya versi tema terang yang lebih gelap/kontras. Kedua
           file diarahkan pakai token baru ini (bg-rx-blue/10 text-rx-blue,
           dst) supaya ikut menyesuaikan toggle tema seperti opsi warna
           lainnya.
Cara tes : Buka Settings > Customization > RX Colors, set salah satu range
           ke warna Blue/Purple/Orange/Gray, lihat preview-nya di kedua
           tema, lalu cek juga badge RX power di halaman All ONUs.


5) Tombol "Remove" pakai red-400 hardcoded, bukan token danger
--------------------------------------------------------------------------------
Lokasi   : frontend/src/pages/RegisterWizard.tsx (6 titik),
           frontend/src/pages/Tr069Profile.tsx (1 titik),
           frontend/src/pages/ProvisionWizard.tsx (1 titik)
Masalah  : Tombol hapus SSID/service/entry di wizard registrasi ONU pakai
           text-red-400 + hover:text-red-300 / hover:bg-red-500/10 —
           warna merahnya sedikit beda dari token --color-danger yang
           dipakai tombol destructive lain di app, dan lebih pucat/kurang
           kontras di tema terang.
Perbaikan: Disamakan ke text-danger hover:text-danger/70 (atau
           hover:bg-danger/10 untuk varian ikon), supaya semua tombol
           "hapus" di seluruh app konsisten satu warna.
